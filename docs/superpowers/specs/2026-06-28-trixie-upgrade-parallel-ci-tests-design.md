# Design: Debian trixie upgrade + parallel CI build-chain tests

Date: 2026-06-28
Repo: `platformio-docker-build` (THiNX embedded build image)

## Goal

Upgrade the build image base OS from `debian:bookworm-20250929-slim` to
`debian:13.5-slim` (Debian 13 "trixie"), while:

1. Capturing a **baseline install log on the old bookworm distro first**, so
   bookworm→trixie toolchain incompatibilities are diffable.
2. Making the image's embedded build-chain **testable** for three dummy
   projects, with the tests running **in parallel on CircleCI after a single
   base image build**.

## Order of operations

The baseline log MUST be captured against the **unmodified** bookworm
`Dockerfile` before any edits. Sequence:

1. Capture baseline (bookworm, arm64, local).
2. Modernize `dummy-esp32-idf` to ESP-IDF 5.3 (idf.py/CMake).
3. Add `tests/` build scripts.
4. Add `Dockerfile.test.amd64` / `Dockerfile.test.arm64`.
5. Rewire `.circleci/config.yml`.
6. Bump production `Dockerfile` to `debian:13.5-slim` (done last so the
   baseline build above runs against bookworm).

## 1. Baseline capture

- Run the **current, unmodified** Dockerfile on arm64 with plain progress and
  tee the log:
  ```
  docker buildx build --platform=linux/arm64 --progress=plain \
    -t pio-baseline:bookworm . 2>&1 | tee baseline-install-bookworm-arm64.log
  ```
- Log is **gitignored** (`baseline-install-*.log`), not committed. Kept as a
  local/CI reference artifact for diffing against the trixie build.

## 2. Modernize `dummy-esp32-idf` to ESP-IDF 5.3

The current project uses the legacy GNU-Make IDF build system
(`Makefile` + `main/component.mk`) and APIs removed in IDF 5.x
(`esp_spi_flash.h`, `spi_flash_get_chip_size()`). It cannot build on IDF 5.3.

Changes:

- Add top-level `CMakeLists.txt`:
  ```cmake
  cmake_minimum_required(VERSION 3.16)
  include($ENV{IDF_PATH}/tools/cmake/project.cmake)
  project(hello-world)
  ```
- Add `main/CMakeLists.txt`:
  ```cmake
  idf_component_register(SRCS "hello_world_main.c" INCLUDE_DIRS "")
  ```
- Update `main/hello_world_main.c`: replace removed flash API
  (`esp_spi_flash.h` / `spi_flash_get_chip_size()`) with `esp_flash.h` +
  `esp_flash_get_size()`, per the current IDF hello_world idiom.
- Delete legacy `Makefile`, `main/component.mk`, and stale `sdkconfig`
  (regenerated by `idf.py set-target esp32`).

## 3. Test scripts (`tests/`, copied into image at `/opt/tests/`)

- `build-esp32.sh`     → `cd /opt/dummy-esp32 && pio run`
- `build-esp8266.sh`   → `cd /opt/dummy-esp8266 && pio run`
- `build-esp32-idf.sh` → `cd /opt/dummy-esp32-idf && . "$IDF_PATH/export.sh" && idf.py set-target esp32 && idf.py build`
- `run-all-local.sh`   → runs all three (local arm64 convenience).

Each script is `set -e` and prints a clear pass/fail line.

## 4. Production `Dockerfile` → `debian:13.5-slim`

- `FROM debian:bookworm-20250929-slim` → `FROM debian:13.5-slim`.
- Bump `LABEL version` to `1.8.96`.
- Package list kept identical initially; the trixie build surfaces any
  renamed/removed packages, fixed as they appear (baseline log is the
  reference for "what worked before").
- Production image otherwise unchanged — keeps its inline esp32/esp8266
  warm-builds and `COPY tests /opt/tests`.

## 5. `Dockerfile.test.amd64` / `Dockerfile.test.arm64`

- Clones of the trixie Dockerfile, differing only by the platform pin:
  - amd64: `FROM --platform=linux/amd64 debian:13.5-slim`
  - arm64: `FROM --platform=linux/arm64 debian:13.5-slim`
- **Inline esp32/esp8266 `pio run` steps removed.** The test image provides
  toolchain + dummy sources + `/opt/tests`; the three builds run as separate
  CI jobs (otherwise esp32/esp8266 would be baked in and the tests would be
  no-ops).
- Trade-off: ~3 near-identical Dockerfiles to keep in sync. Accepted; noted
  for maintenance.

## 6. `.circleci/config.yml`

Follows sibling repo conventions (`circleci/docker@2.8.0`, `docker/docker`
executor, `docker/check` → `docker/build` with `dockerfile:` → `docker/push`
with `digest-path`, `dockerhub` context, `requires:` + branch filters).

Image is shared across jobs **by digest** (only a ~30-byte digest file crosses
the workspace, not the image):

- **`build-base`**: `docker/check` → `docker/build`
  (`dockerfile: ./Dockerfile.test.amd64`, image
  `suculent/platformio-docker-build`, tag `ci`) → `docker/push` with
  `digest-path: /tmp/digest.txt` → `persist_to_workspace` the digest file.
- **`test-esp32` / `test-esp8266` / `test-esp32-idf`**: each
  `requires: [build-base]`, `attach_workspace`, `setup_remote_docker`,
  `docker pull suculent/platformio-docker-build@<digest>`, then
  `docker run --rm <image>@<digest> /opt/tests/build-<target>.sh`.
  → three jobs run in parallel after the single base build.
- **`deploy-docker-build`**: `requires:` all three tests, `master` only,
  pushes `:latest` from the production `Dockerfile`.

## 7. `.gitignore`

Add: `baseline-install-*.log`, `dummy-esp32-idf/build/`,
`dummy-esp32-idf/sdkconfig`, `.pio/`.

## Out of scope (flagged, not fixed)

- `cmd.sh`'s runtime ESP-IDF path still calls legacy `make` (line 128),
  inconsistent with the modernized idf.py dummy. Follow-up task.

## Success criteria

- Baseline bookworm install log captured before any edit.
- Production `Dockerfile` and both test Dockerfiles build on `debian:13.5-slim`.
- All three dummy projects build green via `/opt/tests/build-*.sh`.
- CircleCI runs the three tests in parallel after one base image build;
  `:latest` deploys only after all three pass on `master`.
